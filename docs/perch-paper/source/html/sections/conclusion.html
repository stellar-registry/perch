A Perch grant puts an app's spending limit inside the account's own decision, which Lean proofs show accepts only what the rules allow and keeps each window within its cap, and the sign dialog shows the whole request and its effects before the user signs. In the recorded run, once the owner detached spending_limit, the OpenZeppelin account sent {{fact:sim-oz-percall-moved-xlm}} XLM in {{fact:sim-oz-percall-sends}} payments and Perch refused all {{fact:sim-oz-percall-sends}}; these were the only verdicts on which the two differed. oz-policy-builder is ahead in maturity, authoring and expressiveness, and Perch should learn from it.

Future work covers an agent policy engine, in which a root agent holds a Perch grant and hands child agents budgets; recording-based authoring, a front end that turns a recorded transaction into a grant document; three more ideas from oz-policy-builder, namely simulating a grant before install, refusing a capped rule that another rule naming the same key could bypass, and testing on a corpus of real mainnet transactions; a bridge from the Cedar policy language to grant documents; and measuring both designs with exact metering.
