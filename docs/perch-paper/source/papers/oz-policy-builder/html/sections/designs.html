An OpenZeppelin account with oz-policy-builder authenticates the signers and then asks each attached policy; a Perch account decides first, in one function, and authenticates after.

oz-policy-builder in two halves

Off chain, a synthesiser ({{fact:opb-synth-package}}) records a transaction or takes a declared Intent, writes a predicate in the interpreter's wire form, dry-runs it through the interpreter's own check, renders a review, and returns an unsigned install transaction for the owner's wallet. A command-line tool and an MCP server expose the same {{fact:opb-tools-count}} tools (README.md:13-24). On chain, one shared policy-interpreter contract, attached to an OpenZeppelin context rule as a policy, evaluates the stored predicate in enforce on every guarded call (contracts/stellar/policy-interpreter/src/lib.rs:192-277). Much of docs/stellar.md describes Prime, a custody product built on these parts; the interpreter and the synthesiser are what correspond to Perch's engine.

Where the OpenZeppelin account decides

An OpenZeppelin context rule has a scope, an optional valid_until ledger, signers and policies; a policy is a separate contract with the hooks install, uninstall and enforce. In {{fact:oz-v080-tag}} the account checks that each selected rule exists, matches its context and has not expired; refuses a signer on none of the selected rules; authenticates the signers; and then calls each attached policy's enforce (oz8:storage.rs:629-690), in the rule's stored order: address order for the policies the rule was created with, then any added later (oz8:storage.rs:830, 1304). A policy that refuses rolls back the whole call, including what earlier policies wrote.

Where the Perch account decides

A Perch account attaches no policies. Its __check_auth runs a few guards and then the evaluator, rule_eval::authorize, linked into the account. The evaluator takes the selected rules, their spending records, the contexts, one rule index per context, the claimed signers, the ledger and the grant generation, and returns the next records or a refusal; it reads no storage and checks no signature. Only after it accepts does the account authenticate each signer through its verifier contract, and only then does it write the records (crates/perch-smart-account/src/gate.rs:56-123). Perch's deployed build {{fact:perch-deployed-source-short}} used the attached-policy shape on a fork of OpenZeppelin's account library; the design compared here moved the decision into the account.

Three more ideas from oz-policy-builder

  • Predicate. The interpreter's stored expression for one (account, rule) pair. It has no not, and its ne and nin deny when an operand does not resolve (policy-interpreter/README.md:632-639).
  • Execution adapter. A contract that runs a batch of calls atomically, because Soroban allows one host-function invocation per transaction. A predicate on its execute can relate the calls in the batch (docs/stellar.md:191-195).
  • Keyless rule. A rule with no signer, which the interpreter admits only when it is bound to an execution adapter; anyone may then run what the predicate permits (lib.rs:210-223). Perch refuses a rule with no signer.
