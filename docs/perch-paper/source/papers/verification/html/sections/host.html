A Lean model of Soroban's host shows that an account's __check_auth sees every call its entry approves. The model is tested against the host, not proved equal to it.

{{ref:def:host-run}} models soroban-env-host running a transaction of contract calls under enforcing authorization: every call is a frame that a failure rolls back, and require_auth of an address holds either by invoker authority or by a matching authorization entry, whose first match runs the address's __check_auth on the entry's contexts in preorder. The modeled account is an abstract program checking the stateless allows of {{ref:def:rules-and-allows}}, not Perch's shell.

{{statements:T11}}

{{ref:stmt:authorization-tree-coverage}} answers a question every account design must: does the account see the whole call tree, or only its root? In the model, it sees the tree in preorder, root first, and never an empty batch, which is why the evaluator's acceptance of an empty batch never matters on chain. Authorization by invoker, as in the owner's execute, falls outside the statement by construction.

The model's fidelity is tested, not proved. It was run against {{fact:host-model-tested-versions}} on {{fact:host-traces-generated}} traces it generated and {{fact:host-traces-transcribed}} transcribed from the host's own tests, and agreed on every case it expresses ({{fact:host-cases-agreeing}}). The host used by soroban-sim in the Perch papers, {{fact:soroban-env-host-sim}}, was not among the tested versions.
