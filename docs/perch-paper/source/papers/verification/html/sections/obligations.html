What a signature binds

Let \(H\) be SHA-256, \(\mathit{id}_A\) the account's {{fact:contract-id-bytes}}-byte contract ID, \(\tau\) the tag {{fact:auth-domain-tag}}, \(\mathit{ids}\) the selected rule IDs, and \(P\) the host's signature payload: the hash of the XDR HashIdPreimage::SorobanAuthorization over the network ID, nonce, expiration ledger and invocation tree. The account computes

\[B = H(\tau\,\mathrm{‖}\,\mathit{id}_A\,\mathrm{‖}\,P) \\ D = H\bigl(B\,\mathrm{‖}\,\mathrm{XDR}(\mathit{ids})\bigr)\]

and an external signer signs \(D\). \(P\) is the payload for a legacy Address credential; AddressV2 and delegated entries, from CAP-0071 {{cite:cap-0071}}, hash SorobanAuthorizationWithAddress, which adds the account. A delegated signer approves the host's address-bound payload, which omits \(\mathit{ids}\). OpenZeppelin {{fact:oz-v080-tag}} {{cite:oz-stellar-accounts}} has an external signer sign the hash of AuthDigestPreimage over the account, the payload and the rule IDs, and a delegated signer authorize that preimage through require_auth_for_args; its {{fact:oz-v072-tag}} line signs \(H(P\,\mathrm{‖}\,\mathrm{XDR}(\mathit{ids}))\), without the account. The following is a paper proof, not mechanized.

Lemma 1 (binding). Suppose the verifier named for an external signer correctly verifies an EUF-CMA-secure scheme and \(H\) is collision resistant. An adversary given signatures on \(D(t_1), \dots, D(t_q)\), for tuples \(t_i = (A, \mathit{nid}, \mathit{nonce}, \mathit{exp}, \mathit{inv}, \mathit{ids})\) of its choice, outputs a new tuple \(t\) with a signature accepted on \(D(t)\) only with negligible probability.

Proof. The map from the tuple to \(D\) composes injective encodings with \(H\). XDR encodes \((\mathit{nid}, \mathit{nonce}, \mathit{exp}, \mathit{inv})\) injectively, and its union discriminant separates the two credential forms; \(\tau\) is a constant, and \(\mathit{id}_A\) and \(P\) have fixed lengths, so \((A, P) \mapsto \tau\,\mathrm{‖}\,\mathit{id}_A\,\mathrm{‖}\,P\) is injective; \(B\) has a fixed length and the XDR of \(\mathit{ids}\) is self-delimiting, so \((B, \mathit{ids}) \mapsto B\,\mathrm{‖}\,\mathrm{XDR}(\mathit{ids})\) is injective. If \(D(t) = D(t_i)\) for some \(i\), the injective encodings give a collision of \(H\); otherwise the output is a forgery. For WebAuthn, the signed message carries \(D\) as the client-data challenge. ∎

The lemma covers signatures on \(D\) values only; a key that also signs elsewhere, such as a Stellar account key, is covered only if no message it signs there can equal a \(D\) value.

Non-binding. \(D\) does not depend on the contents of the rules \(\mathit{ids}\) names, on the account's revision, on the other entries of the transaction or on its fee payer; none of these enters \(P\), \(B\) or \(D\). For a delegated signer, the payload the host has it approve depends on the account but not on \(\mathit{ids}\).

Domain tags

Perch separates its hash domains with the tags {{fact:auth-domain-tag}} (the account-bound payload \(B\), scheme {{fact:auth-scheme-name}}), {{fact:domain-tag-rule}} (one rule's bytes), {{fact:domain-tags-recovery}} (recovery statements, configurations, credentials and replacement sets), and, as Poseidon2 constants, {{fact:domain-tags-zk}}. CANON document hashes carry no tag; instead, three theorems of Perch's canonical-encoding package (configPreimage_ne_emitDoc, rulePreimage_ne_configPreimage, rulePreimage_ne_emitDoc) prove that configuration, rule and document preimages never coincide. The rest is argued by inspection, not proved: each SHA-256 tag begins its preimage and none is a prefix of another, so preimages from different domains differ; each Poseidon2 tag is the SHA-256 of its label reduced modulo the field's order, and Poseidon2's length-encoded initial value keeps hashes of different arity apart. For comparison, oz-policy-builder uses {{fact:opb-domain-tags}}.
