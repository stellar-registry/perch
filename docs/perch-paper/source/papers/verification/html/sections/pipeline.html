One Rust source takes two paths: one is translated into Lean, where the theorems are checked, and one is compiled into the account's Wasm, which is tested.

The evaluator is about {{fact:rule-eval-lines}} lines of dependency-free, no_std Rust that forbids unsafe code. It is written in a subset that Aeneas can translate: no traits, closures or iterator adaptors, and every loop a while over one slice.

Three tools connect that Rust to proofs. The Rust compiler lowers code to MIR, its mid-level intermediate representation. Charon reads the MIR that rustc {{fact:rustc-mir-nightly}} produces, and Aeneas {{cite:aeneas}} translates it into a pure functional program in Lean, a proof assistant whose small kernel checks every proof. The translation is a generated {{fact:extracted-lean-lines}}-line Lean file, and equivalence theorems relate it to the readable model, written by hand. rule-core's CI regenerates the translation and fails on any difference, so the Lean file the theorems are about is the one the pinned Rust produces.

The account does not ship that translation. It ships WebAssembly compiled by rustc {{fact:rustc-perch}}, and nothing checks the Wasm against the translation. {{ref:fig:fig-proof-paths}} draws the two paths. Tests bridge them ({{ref:sec:obligations}}); the proofs do not.
