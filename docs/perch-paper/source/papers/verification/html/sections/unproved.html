The proofs cover the decision function's translation, not the compiled contract, the code around it, the host, or what happens outside an authorization.

The proofs and the binary

The theorems are about the translation of the MIR that rustc {{fact:rustc-mir-nightly}} produces. rule-core's CI also builds the evaluator with rustc {{fact:rustc-rule-core-stable}}, Perch builds its contracts with rustc {{fact:rustc-perch}}, and nothing checks the Wasm against the translation ({{ref:fig:fig-proof-paths}}). Release builds keep overflow checks and abort on panic, and allocation failure and stack exhaustion, which the functional model omits, also trap, so each fails the transaction rather than authorizing. The specification is itself trusted: the denotation functions; the document meaning Doc.allows, written from Perch's earlier account ({{fact:doc-allows-source}}, on OpenZeppelin's library at {{fact:oz-fork-pin}}) and not re-derived from the pinned gate; and the Soroban host models.

The shell and the host

Tested, not proved: the JSON parser and compiler, stored-value decoding, rule-ID resolution, context conversion, assembly of the excluded set, spending-record persistence, the credential index, the generation update, the composition of evaluation with authentication, and the recovery controller's state machine. The integration tests run the account's real __check_auth under enforcing authorization, but as natively registered contracts; the Wasm, with passkeys and real proofs, runs in Perch's release_stack.rs flows and on testnet. The host models are tested against selected traces, not proved equivalent to soroban-env-host, and leave out TTL, archival, fees, footprints and validation before the host runs; soroban-sim, the host the Perch papers' simulations use, is another tested host integration. No single theorem covers the whole pinned gate, including mixed administrative and grant batches, so {{ref:stmt:from-the-evaluator-to-the-account}} is argued, not proved.

Proofs that would close gaps (proposed)

  • A Lean lemma for obligation O2, so that selection and renumbering of rules carry the evaluator's theorems to the account by proof rather than by argument and tests.
  • Checking the compiled evaluator directly: Komet {{cite:komet}}, a formal-verification tool for Soroban Wasm, run over rule_eval's Wasm.
  • A host-model statement for authorization by invoker, which {{ref:stmt:authorization-tree-coverage}} leaves out by construction; the owner's execute is its example.
  • A proof that Perch's compiler emits only valid documents (O5), and a theorem connecting the canonical encoding to rule-core's document type.

All four are proposed. No external audit of Perch has been completed.
