A proposed bridge from Cedar to Perch's rules, checked in Lean. Beyond an offline prototype (the Cedar walkthrough) and one unpublished experiment, it is not built.

Cedar {{cite:cedar}} is an authorization language whose semantics are specified and verified in Lean {{cite:cedar-vgd}}. The Lean library of cedar-spec {{cite:cedar-spec}}, Cedar's formal specification, loads unchanged into the Lean toolchain of rule-core's proofs {{cite:rule-core}}. Both semantics are total definitional interpreters, Lean functions rather than relations, so a simulation between them is one commuting equation: Cedar's verdict on an encoded request equals rule-core's verdict on the compiled rule. In an unpublished experiment we proved that equation for a cut-down fragment, with no sorry (Lean's placeholder for a missing proof), and composed Cedar's allowed_iff_explicitly_permitted_and_not_denied, the fragment's simulation and rule-core's allows_eq down to the extracted Rust.

Perch would borrow Cedar's specification as a source language, not its large proofs. The proposed route is a compiler from a Cedar fragment to rule-core rules, verified in Lean against Cedar's semantics, with each installed rule set checked in Lean's kernel against that compiler. Three limits are known. cedar-spec and Aeneas each fix a Lean version, so the two must move in step. Cedar's integers are 64-bit, so the bridge holds only for amounts in that range, not for every i128. And Cedar's parser is tested against its specification, not proved.

The Cedar walkthrough's Perch section describes an offline compiler prototype, its accepted and rejected inputs, and the validation and proof work still required.
