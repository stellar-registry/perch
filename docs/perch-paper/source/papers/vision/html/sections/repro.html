Build and verification

The embedded source bundle contains the Rust JSON-command driver, native entry point, WASI shim, worker, frontend bundle source, dependency locks, contract build script, golden input sequence and comparison checker. The same commands can be supplied to the native program or the WASI runner. The buttons after {{ref:tab:tab-artifacts}} download the source bundle, the build manifest and the reference commands; extract the bundle and follow projects/perch-browser/README.md for the prerequisites, pinned build commands, regression checks and packaging instructions.

Symbol and encoding correspondence

The demo's driver calls the exports of {{ref:tab:tab-api}} and deploys nothing. The embedded contracts are built from the unmodified pinned source, but, like Perch's build-stack.sh, the build rewrites the account's committed infrastructure pin files with the hashes of the compiler and the Perch {{fact:perch-deployed-account-version}} policy contracts built in the same run, so the embedded account ({{fact:embedded-account-short}}) differs from a committed-pin build and from the testnet account ({{fact:preview-account-wasm-short}}).

Wall time depends on hardware, Wasm compilation and browser scheduling; it is displayed as a local observation. Host instructions come from the simulator result on applied steps. A refusal caught during preparation has no reported applied-step count. Raw results retain the diagnostic error rather than replacing it with a client-side policy explanation.
