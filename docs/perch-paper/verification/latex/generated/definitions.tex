\begin{perchdefinition}{1}{Contexts and authorizations}\label{def:contexts-and-authorizations}
\[\begin{aligned}&c \;::=\; \mathsf{call}(C, f, \vec v) \;\mid\; \mathsf{create}(w)\\
&a = (\vec c, \vec j, S, \ell, g)\end{aligned}\]
A context is one call or contract creation in an authorization entry's invocation tree. An authorization \(a\) carries the entry's contexts \(\vec c = c_1, \dots, c_n\) in preorder, root first; one rule index \(j_i\) per context; the claimed signers \(S\); the ledger \(\ell\); and the account's grant generation \(g\).\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Chain.lean\#L114}{Chain.Context}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Authorize.lean\#L80}{Authorization}}

\begin{perchdefinition}{2}{Rules and \emph{allows}}\label{def:rules-and-allows}
\[\begin{aligned}&\mathit{allows}(r, c, S) \iff \mathit{sc}_r(c) \land \bigwedge_{\varphi \in \Phi_r} \varphi(c)\\
&\qquad\qquad \land\ k_r \le |\Sigma_r \cap S|\\
&\mathit{allows}(R, c, S) \iff \exists r \in R.\ \mathit{allows}(r, c, S)\\
&R' \sqsubseteq R \iff \forall c, S.\ \mathit{allows}(R', c, S)\\
&\qquad\qquad \implies \mathit{allows}(R, c, S)\end{aligned}\]
A rule \(r\) has a scope \(\mathit{sc}_r\) (one contract and a function list; false on creations), argument conditions \(\Phi_r\), signers \(\Sigma_r\) and a threshold \(k_r\) over distinct signers, and optionally a cap \((\lambda_r, P_r)\), a last ledger \(u_r\) and a generation \(g_r\). \emph{allows} reads none of the last three; \emph{checkAuth} checks them. A rule set allows what one of its rules allows; \(R' \sqsubseteq R\) when \(R\) allows, under the same signers, everything \(R'\) allows.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/RuleSet.lean\#L95}{Rule.allows}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/RuleSet.lean\#L98}{RuleSet.allows}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/RuleSet.lean\#L126}{RuleSet.narrower}}
\end{perchdefinition}
\begin{perchdefinition}{3}{\emph{checkAuth} and runs}\label{def:check-auth-and-runs}
\[\begin{aligned}&\mathit{checkAuth}(R, \rho, (\vec c, \vec j, S, \ell, g)) = \rho' \iff\\
&\quad |\vec j| = |\vec c| \land |\rho| = |R|\\
&\quad \land\ \forall i.\ j_i < |R| \land \ell \le u_{r_i} \land g_{r_i} \in \{\bot, g\}\\
&\qquad\qquad \land\ \mathit{allows}(r_i, c_i, S)\\
&\quad \land\ \forall s \in S.\ \exists i.\ s \in \Sigma_{r_i}\\
&\quad \land\ \rho' = \mathit{charge}(\cdots \mathit{charge}(\rho, c_1, j_1) \cdots, c_n, j_n)\end{aligned}\]
Here \(r_i = R_{j_i}\). \(\mathit{charge}(\rho, c, j)\) leaves \(\rho\) unchanged when \(R_j\) has no cap; otherwise it reads the amount \(c\) carries, refusing a call that carries none, and applies Definition 4's check to rule \(j\)'s record. Each charge must succeed. \emph{checkAuth} returns the next records or the first refusal, and a refusal changes nothing. A run applies authorizations in order, keeping the records on a refused one.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Authorize.lean\#L147}{RuleSet.checkAuth}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Theorems/Authorize.lean\#L182}{RuleSet.checkAuth\_eq\_ok\_iff}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Authorize.lean\#L168}{RuleSet.run}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Authorize.lean\#L178}{RuleSet.Accepts}}

\begin{perchdefinition}{4}{Window, check and \emph{spent}}\label{def:window-check-and-spent}
\[\begin{aligned}&\mathit{inWindow}_P(L, t) \iff \max(0,\, L - P) < t \le L\\
&\mathit{check}_{\lambda, P}(h, \ell, x) = h' \;\land\; x > 0 \implies\\
&\qquad \sum_{k:\ \mathit{inWindow}_P(\ell,\, t_k)} y_k \;+\; x \;\le\; \lambda\\
&\qquad \land\ h' = ((t_k, y_k))_{k:\ \mathit{inWindow}_P(\ell,\, t_k)}\\
&\qquad\qquad \cdot\, (\ell, x)\end{aligned}\]
A record is a list \(h = ((t_k, y_k))_{k=1}^{m}\) of positive charges in ledger order, its total their sum. The check of a charge \(x\) at ledger \(\ell\) refuses \(x < 0\); accepts \(x = 0\), leaving \(h\); and otherwise refuses a ledger before the newest charge, an overflow, \fact{evaluator-history-bound} entries already kept, or a window total above \(\lambda\). On acceptance it keeps the entries in the window at \(\ell\) and appends \((\ell, x)\). \(\mathit{spent}_j(R, \rho, \vec a)\) lists \((\ell_a, x)\) for each positive charge that the accepted authorizations of run \(\vec a\) make to rule \(j\), in order.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Cap.lean\#L205}{Params.inWindow}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Cap.lean\#L122}{Params.check}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Model/Authorize.lean\#L200}{RuleSet.spent}}
\end{perchdefinition}
\begin{perchdefinition}{5}{Derivation}\label{def:derivation}
\[\begin{aligned}&\mathit{Derives}(R, R)\\
&\mathit{Derives}(R, R') \land \mathit{attenuate}(R', \sigma) = R''\\
&\qquad \implies \mathit{Derives}(R, R'')\end{aligned}\]
\(\sigma\) is one of rule-core's ten attenuation steps: drop a rule; remove functions, or restrict functions; add an argument condition; remove signers, or raise a threshold; add a cap, lower its limit, or lengthen its period; set or lower the last ledger. No step changes a rule's target or generation. \(\mathit{attenuateAll}(R, \vec\sigma) = R'\) applies a list of steps and implies \(\mathit{Derives}(R, R')\).\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Chain.lean\#L442}{Chain.RuleSet.Derives}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Chain.lean\#L423}{Chain.RuleSet.attenuate}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Chain.lean\#L410}{Chain.Attenuation}}

\begin{perchdefinition}{6}{Documents and lowering}\label{def:documents-and-lowering}
\[X = \mathit{excluded}(d_s, A)\]
For a document \(d\) on account \(A\), \(\mathit{Doc.allows}(d, A, c, S)\) holds when some rule of \(d\) covers \(c\)'s contract and function, its argument constraints hold and its principals are signed by \(S\); no rule allows a creation. \(\mathit{Doc.Valid}(d)\) holds when every rule that requires all its signers names distinct signers, fewer than \(2^{32}\) of them, and no rule has a not-after ledger of 0. \(\mathit{lower}(d, A)\) is the rules of an account document, followed by the recovery rule when \(d\) configures recovery. With \(X = \mathit{excluded}(d_s, A)\) for the account document \(d_s\), which is \(A\), the adopted controller and, if configured, the zero-knowledge adapter and pool, \(\mathit{lowerScoped}(d, A, X, g)\) refuses a document that configures recovery or has a rule whose target is \(A\), a member of \(X\) or the account's self-administration, and otherwise lowers \(d\)'s rules stamped with generation \(g\). Document conditions lower to rule-core's \fact{rule-core-conditions} as Table~\ref{tab:tab-attenuation} says; a cap adds the upper bound of the largest \code{i128} on argument 2, a type guard.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Document.lean\#L236}{Doc.allows}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Document.lean\#L358}{Doc.Valid}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Lowering.lean\#L133}{Doc.lower}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Lowering.lean\#L151}{Doc.excluded}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Lowering.lean\#L177}{Doc.lowerScoped}}

\begin{perchdefinition}{7}{Account events}\label{def:account-events}
\[\begin{aligned}&\mathsf{applyDoc}(d'):\ (A, d_s, g) \mapsto (A, d', g)\\
&\mathsf{completeRecovery}(t):\\
&\quad (A, d_s, g) \mapsto (A, t, g + 1) \quad (g < 2^{64} - 1)\\
&\mathit{issue}((A, d_s, g), d)\\
&\quad = \mathit{lowerScoped}(d, A, \mathit{excluded}(d_s, A), g)\end{aligned}\]
An account state \(s = (A, d_s, g)\) is the account's address, its account document and its grant generation. \(\mathsf{applyDoc}(d')\) replaces the account document; \(\mathsf{completeRecovery}(t)\) installs the recovery target \(t\) and advances the generation, and is refused when \(g\) is the largest \code{u64}. A refused event leaves the state unchanged. \(\mathit{run}(s, \vec e)\) applies events in order, and \(\mathit{completions}(s, \vec e)\) counts the completed recoveries among them. A grant document \(d\) is \emph{issued} in \(s\) by lowering it under the account's address, the excluded set of its account document and its generation.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Account.lean\#L50}{Account.step}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Account.lean\#L58}{Account.run}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Account.lean\#L66}{Account.completions}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Vocab/Account.lean\#L76}{Account.issue}}

\begin{perchdefinition}{8}{Host run}\label{def:host-run}
A model of soroban-env-host running a transaction of contract calls under enforcing authorization. Every call is a frame that a failure rolls back. \code{require\_auth} of an address holds when the frame's direct caller is that address (invoker authority), or when an authorization entry of the address matches; on its first match the address's \code{\_\_check\_auth} runs on the entry's contexts in preorder, then the expiration is checked and the nonce consumed. Stellar-account signers, \code{require\_auth} inside \code{\_\_check\_auth}, \code{require\_\allowbreak{}auth\_\allowbreak{}for\_\allowbreak{}args}, \code{authorize\_\allowbreak{}as\_\allowbreak{}current\_\allowbreak{}contract}, contract creation as a call and source-account credentials are outside the model.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Soroban/Host.lean\#L342}{Soroban.Tx.run}}
\end{perchdefinition}
\begin{perchdefinition}{9}{Denotation}\label{def:denotation}
\[\forall x.\ \exists y.\ f_{\mathrm{T}}(x) = \mathsf{ok}(y) \land \llbracket y \rrbracket = f(\llbracket x \rrbracket)\]
\(\llbracket \cdot \rrbracket\) maps the translation's values (byte vectors, \code{u32} and \code{u64} scalars, rules, caps, records, contexts, signers and outcomes) to the model's. A translated function \(f_{\mathrm{T}}\) agrees with its model \(f\) when, for every input, it succeeds and its result denotes the model's result on the denoted input. Theorem~\ref{stmt:total-equivalence-of-the-evaluator} and Theorem~\ref{stmt:lowering-equivalence} are stated this way.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Equiv/Denote.lean\#L108}{Equiv.denoteRules}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/a3c92ba074dcac4052727b7599e5fd8674af6c0a/formal/RuleCore/Equiv/Authorize.lean\#L60}{denoteAuthorized}}
\end{perchdefinition}
