\begin{perchdefinition}{3}{\emph{authorize} and runs}\label{def:authorize-and-runs}
\[\begin{aligned}&\mathit{authorize}(R, \rho, (\vec c, \vec j, S, \ell, g)) = \rho' \iff\\
&\quad |\vec j| = |\vec c| \land |\rho| = |R|\\
&\quad \land\ \forall i.\ j_i < |R| \land \ell \le u_{r_i} \land g_{r_i} \in \{\bot, g\}\\
&\qquad\qquad \land\ \mathit{allows}(r_i, c_i, S)\\
&\quad \land\ \forall s \in S.\ \exists i.\ s \in \Sigma_{r_i}\\
&\quad \land\ \rho' = \mathit{charge}(\cdots \mathit{charge}(\rho, c_1, j_1) \cdots, c_n, j_n)\end{aligned}\]
Here \(r_i = R_{j_i}\). \(\mathit{charge}(\rho, c, j)\) leaves \(\rho\) unchanged when \(R_j\) has no cap; otherwise it reads the amount \(c\) carries, refusing a call that carries none, and applies Definition 4's check to rule \(j\)'s record. Each charge must succeed. \emph{authorize} returns the next records or the first refusal, and a refusal changes nothing. A run applies authorizations in order, keeping the records on a refused one.\leannames{\repolink{https://github.com/bitswell/soroban-rule-core/blob/cbabe594ae2df408991e825e56ddd618ea29541b/formal/RuleCore/Model/Authorize.lean\#L147}{RuleSet.authorize}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/cbabe594ae2df408991e825e56ddd618ea29541b/formal/RuleCore/Theorems/Authorize.lean\#L182}{RuleSet.authorize\_eq\_ok\_iff}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/cbabe594ae2df408991e825e56ddd618ea29541b/formal/RuleCore/Model/Authorize.lean\#L168}{RuleSet.run}; \repolink{https://github.com/bitswell/soroban-rule-core/blob/cbabe594ae2df408991e825e56ddd618ea29541b/formal/RuleCore/Model/Authorize.lean\#L178}{RuleSet.Accepts}}
