# CAP-0071 delegated auth and invoker auth: what recovery relies on

Perch pins a fork of OpenZeppelin's `stellar-accounts`
(`theahaco/stellar-contracts-OZ` at `82002206b1da48167091f33fe2ecfc97ce915857`,
the root `Cargo.toml`'s `stellar-accounts` entry). The fork's one change from
upstream `fbfde38`: `Signer::Delegated` authenticates through CAP-0071
`delegate_account_auth` (protocol 27), carried inside the account's single
`AddressWithDelegates` auth entry, instead of one
`require_auth_for_args((auth_digest,))` entry per delegate. Epic #99
continues on this fork; moving to upstream OpenZeppelin is tracked
separately, once upstream adopts the change.

This page lists every property of that fork and of `soroban-env-host` 27
that [`spec.md`](spec.md) depends on. Each property is pinned by a test in
`crates/integration-tests/tests/cap71_semantics.rs` under **enforcing**
authorization (`set_auths`). `mock_all_auths` never invokes a custom
account's `__check_auth`, so it cannot test any of these. If a dependency
bump changes one of these behaviours, that test fails, and the spec section
named in its row must be revisited.

## What the spec does not rely on

- **Rule selection binding for delegated signers.** See C4.
- **`uninstall` as a gate.** OZ's `remove_context_rule` calls a policy's
  `uninstall` through `try_uninstall` and discards a failure, so no policy
  can block its own removal. Configuration writes happen in `rcv_sync`
  (§10); `uninstall` is a no-op.
- **`mock_all_auths` results.** Recording mode skips `__check_auth`. Any
  recovery test that claims an authorization property must run under
  `set_auths`, as these do, or drive `do_check_auth` directly
  (AGENTS.md, "Soroban auth mocking never invokes a custom account's
  `__check_auth`").

## Nesting and reuse limits

The host matches each delegate at most once per authentication frame (a
second `delegate_account_auth` for the same address fails), and nested
delegates must be sorted and unique in the credentials. Recovery uses no
nested delegation of its own. A guardian or owner that is itself a smart
account with delegates works through the same host path, one level down.
